# 架构说明

## 总览

“去你的广告”是单 APK、离线、事件驱动的 Android 应用。核心数据流如下：

```text
AccessibilityEvent / 窗口变化
              |
              v
      前台归属与安全门禁
              |
       +------+------+
       |             |
       v             v
  LTT / GKD       SDK 特征识别
   规则匹配           |
       +------+------+
              |
       明确且唯一的目标？ ---- 否 ----> 本地 OCR 兜底
              |
             是
              |
       执行前再次核对状态
              |
        点击或受控手势
              |
       写入本地操作记录
```

## 模块

### `app`

Android 应用模块，包含主界面、辅助功能服务、前台状态服务、规则编排、GKD 适配、SDK 特征识别、OCR 和本地记录。包名为 `org.adguardian.app`。

### `gkd-core`

从上游 GKD 选择器源码生成并保留来源映射的 JVM 模块。负责选择器语法解析、属性表达式、关系选择器和运行时匹配。它也承载不依赖 Android 设备的真实选择器测试。

### 规则资源

- `app/src/main/assets/ltt`：冻结哈希的 LTT 原始规则数据。
- `app/src/main/assets/gkd`：由两份上游来源审查、归一化并生成的广告规则包。
- `third_party`：上游原文、固定提交、来源清单、许可证和哈希证明。

### OCR

应用使用 Tesseract4Android。本地构建脚本按固定 SHA-256 获取 `chi_sim.traineddata`；模型不会在运行时联网下载。OCR 只作为有限时间窗口内的补充证据，不能绕过前台归属和敏感控件门禁。

## 状态与安全不变量

- 跨应用跳转证据一次性消费；前台应用变化或用户输入会使其失效。
- 规则次数、冷却、匹配时限和失败目标隔离相互独立。
- 用户输入只取消挂起动作，不恢复已消耗的规则状态。
- 已执行动作立即记录；“动作被系统接受”不等于“广告已成功关闭”。
- 所有异步操作在执行前后重新检查当前应用、窗口代次和功能开关。

## 构建与发布

Release 工作流运行完整校验与构建，随后用 Android `apksigner` 验证 APK，生成 SHA-256 文件并发布到 GitHub Releases。
